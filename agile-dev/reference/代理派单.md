# agile-dev 代理派单（探索 + 实现）

> 通用探索 agent 与开发 agent 定义（含授权档位表、基础模板、失败政策、轻量直改判据）见《coding-rules》reference·通用代理；本文件只放 agile-dev 的专属变体。

## 一、探索（readonly）

### 派遣规范

| 项 | 值 |
|----|-----|
| 工具 | `Task`，`subagent_type: explore` |
| readonly | **true** |
| 并行 | 1–3 个，同步等待 |
| 失败 | 重试一次 → 手工探索，更新 `docs/apm/memory/` 下的记忆文件 |

### 探索报告（敏捷变体）

```text
1）探索范围
2）发现摘要（与本次 bug/feature 直接相关）
3）证据列表（路径、符号、配置、文档）
4）建议实现/修复方向与风险
5）未弄清项（如有）
```

### prompt 模板

```text
【语言要求】
- 全程使用中文；路径、符号、命令可保留原文

请以 readonly 模式探索下列范围，为敏捷开发提供事实依据（不修改任何文件）。

仓库：<REPO_PATH>
类型：<bug | feature>
所属迭代：<需求名称>
敏捷名称：<敏捷名称>
用户诉求 / 前文结论：<SUMMARY>
探索范围：<SCOPE>

请先列出将阅读的文件/目录，再按「探索报告」结构返回。
```

## 二、实现（inline）

### 派遣规范

| 项 | 值 |
|----|-----|
| 工具 | `Task`，`subagent_type: generalPurpose` |
| readonly | **false**（单次 inline，禁止再拆子代理） |
| 失败 | 重试一次（资源）→ 修正 prompt 重派；震荡 ≥3 → blocked |

授权档位（钦定／骨架／方向）定义见《coding-rules》reference·通用代理——写入 impl prompt，标明用户输入的可信度；**钦定档任何偏离（含顺手重构）即打回**。

### impl Prompt 模板

```text
【语言要求】
- 全程使用中文：任务说明、执行过程、结论、返回报告
- 代码注释与公开 API 文档注释必须使用中文
- commit message 使用中文
- 仅代码标识符、协议字段名、第三方 API 等保持英文

请以 inline 模式（单次连续执行、不拆子代理）完成下列敏捷开发任务。

仓库/worktree：<PATH>
分支：<BRANCH>
类型：<bug | feature>
授权档位：<钦定 | 骨架 | 方向>：<用户原话或要点>
所属迭代：<需求名称>
敏捷名称：<敏捷名称>

探索结论：
<粘贴汇总后的探索结论>

约束：
- 单次运行内完成实现与验证
- 按逻辑块提交；不 revert 无关改动
- 运行与本次改动相关的针对性测试/构建
- 新增/修改代码须写中文注释；公开 API 按项目语言补充文档注释

请严格按以下格式用中文返回：
1）已完成项与剩余缺口
2）提交记录（sha + message）
3）验证命令及通过/失败结果
4）阻塞项（如有）
```
