# 通用代理（探索 / 开发 / CR · 唯一权威）

> 本文件是 coding 族「派子代理」的唯一事实来源：三类通用代理的定义（派遣规范、报告结构、prompt 基础模板）与通用派遣纪律都在这里。各工作流 skill 的**专属变体**（字段增减、检查维度注入）放各自 `reference/`，引用本文件，不得另立拷贝。

## 〇、语言要求块（所有 prompt 开头必带）

```text
【语言要求】
- 全程使用中文：任务说明、执行过程、结论、返回报告
- 代码注释与公开 API 文档注释必须使用中文；commit message 使用中文
- 仅代码标识符、协议字段名、第三方 API 名等保持英文
```

## 一、探索 agent（explore）

**用途**：读代码与文档、取证、理清现状——凡是「要读一大片代码」的活。上下文隔离价值最高，**必须派子代理**，主代理不得自行深入读代码替代。

| 项 | 值 |
|----|-----|
| 工具 | `Task`，`subagent_type: explore` |
| readonly | **true**（禁止修改任何文件） |
| 并行 | 1–4 个（按探索面拆分），**同步等待**全部返回 |
| 失败 | 重试一次 → 主代理手工 readonly 探索，标注「手工探索」 |
| 补派 | 报告有缺口/矛盾时补派聚焦探索，**上限 2 轮** |

**基础报告结构**（skill 变体可增减条目）：

```text
1）探索范围：本任务覆盖的模块/路径/文档
2）发现摘要：与任务直接相关的事实（按重要性排序）
3）证据列表：文件路径、符号、配置项、日志点、文档段落（须可核对）
4）关联与影响：上下游、依赖、同类实现（如有）
5）未弄清 / 矛盾点：无法确认的部分（禁止猜测下结论）
6）建议：补探索方向 / 需用户补充的信息（如有）
```

**基础 prompt 模板**（skill 变体替换 `<目的>` 与字段）：

```text
【语言要求】
- 全程使用中文；路径、符号、命令可保留原文

请以 readonly 模式探索下列范围，<探索目的，如「为 PRD 撰写提供业务现状上下文」>（不修改任何文件）。

仓库：<REPO_PATH>
探索范围：<SCOPE>
<任务上下文字段：用户问题 / 用户诉求摘要 / 需求文档路径 …>

请先列出将阅读的文件/目录，再按「探索报告」结构返回。
禁止修改任何文件；禁止仅凭猜测下结论，找不到的写入「未弄清」。
```

**纪律**：

- 探索报告**仅供当次任务**（答疑/写文档）；**不构成**后续实现阶段跳过 impl 子代理的依据。
- 探索结论须进后续 prompt 或文档的，只摘结论，勿贴报告全文。

## 二、开发 agent（impl / fix / verify）

**用途**：写代码、修 must-fix、跑验证——执行类工作。单次 inline 连续执行，禁止再拆子代理。

| 项 | 值 |
|----|-----|
| 工具 | `Task`，`subagent_type: generalPurpose` |
| readonly | **false**（单次 inline） |
| 并行 | 无同文件冲突可同 wave；**同文件禁止并行 impl/fix** |
| 失败 | 重试一次 → 修正 prompt 重派；同一问题重试 ≤3 次 → **blocked** 请用户拍板 |

**基础返回结构**：

```text
1）已完成项与剩余缺口
2）提交记录（sha + message，无则写「无提交」）
3）验证命令及通过/失败结果
4）阻塞项（如有）
```

**基础 prompt 模板**：

```text
【语言要求】
- 全程使用中文：任务说明、执行过程、结论、返回报告
- 代码注释与公开 API 文档注释必须使用中文；commit message 使用中文
- 仅代码标识符、协议字段名、第三方 API 等保持英文

请以 inline 模式（单次连续执行、不拆子代理）完成下列任务。

仓库/worktree：<PATH>
分支：<BRANCH>
任务：<本节点具体目标，含 spec 步骤 id / fix 条目 id>
授权档位：<钦定 | 骨架 | 方向>：<用户原话或要点>
<任务上下文：探索结论 / Context Bundle / must-fix 清单 …>

约束：
- 单次运行内完成实现与验证
- 按逻辑块提交；不 revert 无关改动
- 运行与本次改动相关的针对性测试/构建

请用中文按下列结构返回：
1）已完成项与剩余缺口
2）提交记录（sha + message）
3）验证命令及通过/失败
4）阻塞项（如有）
```

**授权档位**（写入 impl prompt，标明用户输入的可信度，决定子代理自由度）：

| 档位 | 用户给了什么 | 子代理自由度 |
|------|--------------|--------------|
| 钦定 | 确切改法（改哪、改成什么） | 逐字执行；任何偏离（含顺手重构）即打回 |
| 骨架 | 改哪些点已定 | 怎么改自由，改哪些点不动 |
| 方向 | 只给意图（「把这个 bug 修了」） | 方案与实现自定，验证须过 |

## 三、CR agent（review / evidence）

**用途**：readonly 评审与取证——审查独立性须保留，**主代理禁止自审**。evidence 只取证不下结论；review/judge 禁止仅凭证据包下结论，须回读关键代码。

| 项 | 值 |
|----|-----|
| 工具 | `Task`，`subagent_type: generalPurpose` |
| readonly | **true** |
| 并行 | review-scope 可并行；judge/终审每轮**一个** |
| 失败 | 重试一次 → 主代理手工等效审查，标注「手工审查」 |

**基础返回结构**（评审类）：

```text
1）相对上轮：已修复/已写入 / 仍开放/仍缺 / 新引入/新问题（第 2 轮起）
2）发现（P0/P1/P2 分级），每条含：严重度、问题、证据（路径/章节 + 代码路径）、改法/修改建议
3）open_questions：未认定项，不得混入 must-fix
4）结论：ready 与否 + 一句话理由（由主代理最终判定）
```

**首诊与复审（反锚定）——通用纪律**：

- **首诊**：对某问题域的**首轮**评审——不带既往 must-fix、不带主代理的预设与解读，全新视角找问题。
- **复审**：第 2 轮起——携带上轮条目做「已修复 / 仍开放 / 新引入」回归追踪；仍**不带**主代理对「为什么没修好」的解读，只带条目本身。
- **反锚定自检**（拼派单时必做）：把 prompt 读一遍，凡「我认为 / 我怀疑 / 我倾向 / 疑似根因是 / 问题大概出在」等预设措辞——**全删**。派单里只应剩下：任务、材料与路径、检查范围、上轮条目（复审时）。审查者顺着预设走，独立视角就没了。

**评审纪律**：

- must-fix = **已认定有问题 + 有改法**；没认定 → open_questions，不得进 must-fix。
- 审查子代理禁止：改代码或被审文档；宣布终点态（只给建议，主代理收敛）。

## 四、通用派遣纪律

1. **同步等待**：当前 wave 全部返回后再汇总、决策；禁止未等返回即下结论或派下一环。
2. **失败政策**：重试一次（修措辞，不原样重发）→ 仍失败主代理手工等效完成并标注「手工××」→ 资源恢复后回到子代理流程。**同一问题震荡 ≥3 次 → blocked**，请用户拍板。
3. **轻量直改**（主代理直接执行，适用 impl/fix/verify 类小节点）：派遣价值＝上下文隔离＋并行，两者都不沾时主代理直接干。
   - 快路径：改动集中 1–2 个文件、位置已知、验证输出短；拿不准时以「预估 ≤3 次工具调用」兜底倾向直改。
   - 主判据：**主代理直接执行不会消耗大量上下文**。注意试错预期高（测试反复红、边跑边改）的节点即使文件少也派遣——上下文膨胀发生在试错环节，不在编辑环节。
   - 满足时标 `executor: main`；验证与证据留痕照常——省的是往返，不是省质量。
   - **不适用**：审查类节点（独立性须保留）。
4. **证据包（evidence pack）**：跨轮次/波次重复读的**稳定背景**（模块地图、调用链、约定、既往 findings、diff 统计）落盘复用，**生产者写、消费者读**：
   - 生产者：第一个读该区域的子代理顺手落盘，路径写入 iteration-state/Bundle；主代理只持路径，**不亲自写包**——否则读代码的成本只是转移到了最贵的主代理上下文上。
   - 路径：`docs/iterations/<name>/cache/<topic>.md`（过程产物，不入版本控制；用户另指定则从其指定）。
   - 失效：包头记 `head_sha`/生成节点/范围；sha 不一致 → 视为 stale，仅作线索，事实须新鲜读。
   - 边界：只放稳定背景；**被审/被改的当前对象必须新鲜读**，不得以包替代。
5. **中文协作**：主代理与子代理的协作、说明、文档与回复一律中文（路径、标识符、协议字段等除外）。

## 五、动态 DAG 编排纪律（loop 类 skill 共用）

code-dev-loop / code-review-loop / spec-check-loop 三个 loop 共用的编排纪律；各 skill 的 SKILL.md 只保留**该 skill 特有的动作表与节点类型**，引用本节，不复制条款。

**核心概念**：

- **wave（波次）**：一轮并行派遣。wave 内节点无冲突可并行；**同步等待**全部返回后再汇总、决策。
- **dag_version**：编排版本号。每轮 wave 结束或 not-ready 后改图，`dag_version++`。
- **not-ready**：本轮未达终点态——不是失败，是「改图再来」的信号。
- **node_status**：每个节点的 status / 产物 sha / executor 等记账。

**通用改图动作**：

| 动作 | 何时 |
|------|------|
| **并行化** | 无文件冲突的节点同 wave |
| **合并** | 多个同类节点针对同一模块 → 单节点 |
| **拆分** | 节点过大或反复 fail → 串行子节点 |
| **优先 P0** | 阻塞下游的条目排进下一 wave / 直改计划首部 |
| **插入审查节点** | 实现波次后、下一模块前（**须在 DAG 内显式出现**） |

各 skill 特有动作（dev 的插入 cr-func、review 的两段式、doc-fix 直改等）见各自 SKILL.md。

**状态落盘**：编排状态（`dag_version`、`wave_plan`、`node_status`、open must-fix、fix/doc 计划等）写在 **`docs/.iteration-state.yaml`** 或 Context Bundle / 对话内 YAML，**禁止写入记忆文件**（`docs/apm/memory/` 与 `RULE.md`）——那是 apm-record 的地盘，只放一两句人话现状。会话中断后靠它恢复：done 节点不重跑。

**震荡与终止**：同一 must-fix 震荡 ≥3 次 → **blocked**，停下请用户拍板——真值在用户，不在循环。各 skill 轮次上限（默认 5 轮）见各自 SKILL.md。终点态是**结论**（dev-ready / fix-spec-ready / execute-ready），不是波次节点，不单独派子代理。

**禁止事项**：not-ready 时只「再派一个 fix」而不更新 `wave_plan` / `dag_version`；宣称终点态却未满足其检查清单；未等当前 wave 返回即改图或派下一环；把 DAG/YAML 状态贴进记忆文件。
