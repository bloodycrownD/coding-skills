# prd-generate 代理派单（探索）

> 通用探索 agent 定义见《coding-rules》reference·通用代理；本文件只放 prd-generate 的专属变体（业务视角）。

## 派遣规范（探索）

| 项 | 值 |
|----|-----|
| 工具 | `Task`，`subagent_type: explore` |
| readonly | **true** |
| 并行 | 2–4 个，同步等待 |
| 失败 | 重试一次 → 主代理手工 readonly 探索，标注「手工探索」，记入 memory 文件（人话短句） |

## 探索报告（prd 变体·业务视角）

每条报告须为中文，结构如下：

```text
1）探索范围：本任务覆盖的模块/路径
2）现状摘要：已有能力、用户流程、数据/业务边界（业务视角）
3）与需求相关的缺口或疑点
4）关键证据：文件路径、路由、配置项、已有 PRD 路径（列表即可）
5）建议主代理向用户澄清的问题（如有）
```

## 探索维度参考

| 探索项 | 目的 | APM 辅助 |
|--------|------|----------|
| 相关页面/路由/入口 | 确认用户从哪进入、现有流程是什么 | `apm-recall` 初始化片段（规则 + 最近记忆），不足时直读 `docs/` 下相关文档 |
| 核心模块与服务 | 理解业务边界、已有能力与缺口 | 规则 + 最近记忆，不足时直读 `docs/` 下相关文档 |
| 对外接口/事件/配置 | 判断需求是否涉及上下游或第三方 | 子代理代码探索 + 规则与最近记忆（`apm-recall` 初始化片段） |
| 命名与术语 | 与用户描述对齐，减少歧义 | `apm-recall` 初始化片段（规则 + 最近记忆） |
| 已有 PRD/文档 | 避免重复定义、识别增量需求 | 规则 + 最近记忆，不足时直读 `docs/iterations/` |

## prompt 模板

```text
【语言要求】
- 全程使用中文；路径、符号、命令可保留原文

请以 readonly 模式探索下列范围，为 PRD 撰写提供业务现状上下文（不写技术方案）。

仓库：<REPO_PATH>
探索范围：<SCOPE，如「用户设置页与账号相关路由」>
用户诉求摘要：<USER_GOAL>
请先列出将阅读的文件/目录，再按「探索报告」结构返回。
禁止修改任何文件。
```
